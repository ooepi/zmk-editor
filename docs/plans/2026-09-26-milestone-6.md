# Implementation plan — Milestone 6: GitHub connect, commit, build, download

Spec: [docs/specs/2026-09-26-zmk-editor-design.md](../specs/2026-09-26-zmk-editor-design.md)

## Spike first: artifact download from the browser

The artifact zip URL redirects to Azure blob storage. If that storage sends no CORS headers, the browser can't read the zip.

`.github/workflows/artifact-cors-spike.yml` checks this for real. It uploads a small artifact, then a Chromium page on another origin tries to download it with the job's token, the same way the editor will.

The editor is built to work either way:
- it tries the download;
- if the browser blocks it, it links to the run's artifact page and lets you drop the downloaded `firmware.zip` into the editor, which then extracts the `.uf2` files.

## Core (`src/core/github/`, test-first against a fake GitHub API)

1. **`client.ts`** — a small REST client with the token and an injectable `fetch`. It gives errors that explain what went wrong: a bad token, missing permissions, a missing repo, or rate limits.
2. **`repo.ts`**:
   - `loadRepoConfig` reads the branch's tree recursively, fetches the config files as blobs, and imports them.
   - `commitFiles` makes one commit through the Git Data API: a tree with inline contents on top of the branch head, then the commit, then a ref update. It makes no commit when nothing changed.
3. **`builds.ts`**:
   - `findRunForCommit`;
   - `waitForRun`, which polls with an injectable sleep and reports progress;
   - `downloadFirmware` (artifact list → zip → `.uf2` files). A blocked download raises an error that carries the run's URL.
4. **`firmware.ts`** — `extractUf2` gets the `.uf2` files out of an artifact zip, including zips nested inside it.
5. **`diff.ts`** — a line diff for reviewing what a commit changes.

## UI — Build tab

1. **Connect:**
   - a fine-grained token with Contents read/write, Actions read and Workflows read/write (needed when the build workflow file changes);
   - the repo and branch;
   - kept in this browser's localStorage, as the spec says.
2. **Load from repo** — replaces the editor contents, after asking.
3. **Changes** — the files that differ from the branch, each with a diff. The first commit rewrites files in the editor's format, and the page says so.
4. **Commit & build** — a commit message, then commit, find the build and follow it (queued → running → done), with a link to the run.
5. **Firmware** — one row per `.uf2` with Download, plus "Write to keyboard" where the browser supports the File System Access API (choose the NICENANO drive in bootloader mode), and flashing instructions. The blocked-download fallback is described above.
6. **Latest build** — see the latest run on the branch without committing.

## Tests

- Client error mapping.
- `loadRepoConfig` and `commitFiles`, including the unchanged case.
- `waitForRun` progress and timeout.
- Firmware extraction, including nested zips and the blocked download.
- The line diff.
- A UI flow against the fake API: connect → changes → commit & build → `.uf2` listed.
