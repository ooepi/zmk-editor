# UI overhaul, Phase 1 (app shell): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A top bar of round icon buttons plus a More menu, pill view tabs with icons, and a floating vertical layer rail whose rows reveal grip, rename and delete on hover.

**Architecture:**
- Two new primitives in `src/ui/components/ui/`: `IconButton` and `Menu`. Both render classes defined in `controls.css` and are shown on `/#design`.
- `Toolbar` and the tab row in `App.tsx` are rebuilt on top of those primitives.
- `LayerBar` is replaced by `LayerRail`, which reuses `useReorder` and every existing reducer action.

**Tech Stack:** React 19, vitest + testing-library (jsdom), CSS in `src/ui/styles/`.

**Spec:** `docs/specs/2026-09-29-ui-overhaul-design.md` (Phase 1). Branch `ui/shell`, stacked on `ui/foundation` (PR #31).

## Global Constraints

- Use tokens only; `tokens.test.ts` and `contrast.test.ts` must stay green. State lines use `--accent-line`, fills use `--accent`.
- These accessible names are the tests' contract and must not change:
  - `Undo`, `Redo`, `Open from GitHub`, `Print keymap`, `Open help`, `Dark theme`, `Buy me a coffee` (a link), `Build & flash`, `Add layer`, `Layer name` (the rename textbox)
  - the view tabs `Keymap`, `Combos (N)`, `Behaviors (N)`, `Macros (N)`, `Modules (N)`, `Screens`, `Settings`
  - layer tabs keep `role="tab"`, and their text content stays exactly `<index><name>` (e.g. `0BASE`)
  - the hidden file input keeps `data-testid="config-files"` and is always rendered
- While the keyboard wizard is open (`locked`): Undo, Redo, Open files, Open from GitHub, Print and Reset to demo are disabled with `lockedTitle`, as today. The downloads stay enabled.
- Every new shared control gets a section on the design system page (`/#design`), per `docs/design-system.md`.
- Test runs use `npx vitest run --maxWorkers=6` (the default `npm test` times out randomly on this machine).

## Review Focus

1. **Keyboard use of the More menu.** Arrow keys, Home and End move between the enabled items, Esc closes the menu and returns focus to the trigger, and Tab closes it (Task 2 tests).
2. **Menu actions while the wizard is locked.** The disabled items can't be triggered by click or Enter (Task 2 and Task 3 tests).
3. **Hover-only controls on the rail.** Rename and delete must also be reachable by keyboard: they show on `:focus-within` and are real buttons in the tab order. Alt+↑/↓ moves the focused layer (Task 5 tests).
4. **Deleting a layer that isn't active.** It deletes the layer on that row, not the active one, and the confirmation names that layer (Task 5 test).
5. **Narrow windows (1024 and 800px).** The top bar fits on one row at 1024; at 800 it may wrap, but nothing overflows. The rail doesn't squeeze the keyboard below a usable size (Task 6 visual check).

```tsx
import type { ComponentPropsWithoutRef } from 'react';
import { Icon, type IconName } from '../Icon.tsx';

type IconButtonProps = {
  icon: IconName;
  /** The accessible name, the default tooltip, and the text shown when `expand` is set. */
  label: string;
  /** Show the label next to the icon while hovered or focused. */
  expand?: boolean;
  tone?: 'danger';
} & Omit<ComponentPropsWithoutRef<'button'>, 'children'>;

/** A round icon-only button. The label names it for screen readers and appears as a tooltip. */
export function IconButton({ icon, label, expand, tone, className, title, ...rest }: IconButtonProps) {
  const classes = ['icon-button', expand && 'expandable', tone, className].filter(Boolean).join(' ');
  return (
    <button type="button" {...rest} className={classes} aria-label={label} title={title ?? label}>
      <Icon name={icon} size={18} />
      {expand && <span className="icon-button-label">{label}</span>}
    </button>
  );
}
```
