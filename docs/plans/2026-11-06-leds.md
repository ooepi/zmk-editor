# LEDs (RGB underglow and backlight) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keyboards designed in the wizard (one-piece or split) can have RGB underglow, a single-colour backlight and an LED power switch, and the editor generates a ZMK shield that drives them.

**Architecture:**
- **Model:** a `Leds` block per half (`leds`, `rightLeds`, following the encoders' pattern) and helpers in a new `leds.ts`.
- **Generation:** writes underglow on `&spi3`, backlight on `&pwm1`, and a power pin by retargeting `/EXT_POWER` and holding the board's 3.3 V pin on.
- **Around it:** validation, file format version 4, Settings unlock and auto-on, a wizard "LEDs" fieldset, help and CI fixtures.

**Tech Stack:** TypeScript, React 19, Vite, vitest + testing-library (jsdom), ZMK v0.3 devicetree.

**Spec:** `docs/specs/2026-11-06-leds-design.md`

## Global Constraints

- One chain of GRB addressable LEDs per half; `count` is a whole number from 1 to 256.
- Underglow is always `&spi3` with `spi-max-frequency = <4000000>`, `spi-one-frame = <0x70>`, `spi-zero-frame = <0x40>`, `color-mapping = <LED_COLOR_ID_GREEN LED_COLOR_ID_RED LED_COLOR_ID_BLUE>`.
- Backlight is always `&pwm1` channel 0, `PWM_MSEC(10)`, `PWM_POLARITY_NORMAL`.
- The power pin is active high and retargets `/EXT_POWER`. The board's own 3.3 V control pin is then held on with a `gpio-hog` copying the board's flags (table in Task 1). On a board without `EXT_POWER` (the XIAO), the node is created.
- On a split, the right half copies the left's LEDs unless the right half is wired differently.
- Keyboards without LEDs serialize and generate byte-identically to today. Version 4 is written only when LEDs are present.
- User-facing copy: plain words, sentence case, curly apostrophes (’).
- Run tests with `npx vitest run --maxWorkers=4` (the default run times out at random on this machine). Snapshot fixtures are updated only for the new fixtures (`-u` on `test/customKeyboards.test.ts`); existing ones must not change.
- Shell: the Bash tool's heredocs lose backslashes, so write edit scripts with the Write tool, and keep each file's line endings (`newline=''`).

## Review Focus

1. **Turning the LEDs off must never cut power to the shift registers.** Two cases:
   - With a power pin, the 3.3 V pin is hogged on.
   - Without one, on a keyboard with shift registers, `ZMK_RGB_UNDERGLOW_EXT_POWER` defaults to n.

   Pinned in Task 3 (`Kconfig.defconfig` and hog tests).
2. **Active-low boards** (nice!nano v1, nRFMicro 1.3, Puchi-BLE): the hog must keep 3.3 V on, not off. Pinned in Task 3 (the `nice_nano` hog test uses `GPIO_ACTIVE_LOW` with `output-high`).
3. **Mirrored split:**
   - The right overlay gets the same LED nodes as the left.
   - Ticking "wired differently" copies them, and unticking drops `rightLeds`.

   Pinned in Tasks 1 and 3.
4. **Turning both kinds off** removes the whole `leds` block, power pin included, so an orphaned power pin is never validated or generated. Pinned in Task 1.
5. **Editing a keyboard that already has LEDs** must not switch the setting back on after the user turned it off in Settings. Pinned in Task 4 (`applyHardware` only switches on when the kind is new).
