# UI overhaul, Phase 3 (combos): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make making a combo obvious from start to finish:
- The list shows each combo as a formula, like `[B] + [G] → [Esc]`.
- Editing shows a banner over the keyboard.
- The editor reads ① Keys, ② Sends, ③ Options.
- **Done**, Esc, or a click on empty keyboard space closes it, with a short "Combo saved" toast. Nothing stays selected, so it's clear the combo is saved.

**Architecture:**
- **Formula** (core). `comboParts(combo, model)` in `src/core/keymap/comboEdit.ts` returns the key labels and what the combo sends.
- **Closing the editor** (UI). `App` owns which combo is being edited, so it owns closing it: `finishCombo()` is called by Done, Esc and empty-canvas clicks.
- **Toasts.** Notices gain an optional `transient` flag. A transient notice clears itself after 4 seconds; other notices stay until they're dismissed, as today.
- **Panel.** `CombosPanel` is restyled around the three steps.
- The combo key highlight keeps its amber outline, which you said you liked.

**Tech Stack:** React 19, vitest + testing-library (jsdom).

**Spec:** `docs/specs/2026-09-29-ui-overhaul-design.md`, "Phase 3: Combos flow". Branch `ui/combos` from `main`.

## Global Constraints

- Tokens only; `tokens.test.ts` and `contrast.test.ts` stay green.
- Keep these accessible names: `+ New combo`, the list `Combos`, the layer chips `Combo layers`, and the combo properties' labels. `Print.test.tsx` and `Milestone4.test.tsx` rely on them.
- Edits still apply live and each is one undo step. "Saved" means what it has always meant: saved in this browser.
- A combo with fewer than 2 keys can't be finished. Done shows an inline message instead, and the combo stays open.
- Test runs use `npx vitest run --maxWorkers=6`. After scripted edits, restart the preview server before checking in the browser (see the Vite stale-module note).

## Review Focus

1. **Every way out ends the same way.** Done, Esc and an empty-canvas click all close the editor, clear the highlight and show "Combo saved". An incomplete combo blocks every one of them with the same message (Task 3 tests).
2. **The toast disappears by itself** only when it's transient. Other notices, such as "Removed combos…", still stay until dismissed (Task 2 tests).
3. **The formula stays readable** for combos on keys that have no label (transparent), combos with no keys yet, and combos sending a layer or macro (Task 1 tests).
4. **Esc still works elsewhere.** It keeps deselecting keys and stopping an armed tile on the Keymap view (existing tests stay green).
5. **Undo while a combo is open** doesn't leave the editor pointing at a combo that no longer exists (Task 3 test).

```tsx
// @vitest-environment jsdom
import { act, cleanup, render, screen, within } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { afterEach, beforeEach, describe, expect, it, vi } from 'vitest';
import { App } from './App.tsx';

beforeEach(() => localStorage.clear());
afterEach(() => {
  cleanup();
  vi.useRealTimers();
});

const key = (name: string) => screen.getByRole('button', { name });
const banner = () => screen.getByRole('region', { name: 'Combo keys' });

async function newCombo() {
  const user = userEvent.setup({ advanceTimers: vi.advanceTimersByTime });
  render(<App />);
  await user.click(screen.getByRole('button', { name: 'Combos (0)' }));
  await user.click(screen.getByRole('button', { name: '+ New combo' }));
  return user;
}

describe('making a combo', () => {
  it('asks for keys in a banner and counts them', async () => {
    const user = await newCombo();
    expect(within(banner()).getByText(/Click the keys for this combo/)).toBeTruthy();
    await user.click(key('Key 13: Q'));
    await user.click(key('Key 14: W'));
    expect(within(banner()).getByText(/2 keys/)).toBeTruthy();
  });

  it('finishes with Done: the editor closes, nothing stays highlighted, and it says so', async () => {
    vi.useFakeTimers();
    const user = await newCombo();
    await user.click(key('Key 13: Q'));
    await user.click(key('Key 14: W'));
    await user.click(screen.getByRole('button', { name: 'Done' }));
    expect(screen.queryByRole('region', { name: 'Combo keys' })).toBeNull();
    expect(key('Key 13: Q').className).not.toContain('highlighted');
    expect(screen.getByRole('status').textContent).toMatch(/Combo saved/);
    const list = within(screen.getByRole('list', { name: 'Combos' }));
    expect(list.getByText('Q')).toBeTruthy();
    expect(list.getByText('W')).toBeTruthy();
    act(() => void vi.advanceTimersByTime(4000));
    expect(screen.queryByRole('status')).toBeNull();
  });

  it('finishes with Esc too', async () => {
    const user = await newCombo();
    await user.click(key('Key 13: Q'));
    await user.click(key('Key 14: W'));
    await user.keyboard('{Escape}');
    expect(screen.queryByRole('region', { name: 'Combo keys' })).toBeNull();
  });

  it('will not finish with fewer than two keys, and says why', async () => {
    const user = await newCombo();
    await user.click(key('Key 13: Q'));
    await user.click(screen.getByRole('button', { name: 'Done' }));
    expect(banner()).toBeTruthy();
    expect(screen.getByText('Pick at least two keys, or delete this combo.')).toBeTruthy();
  });

  it('closes the editor if undo removes the combo', async () => {
    const user = await newCombo();
    await user.click(screen.getByRole('button', { name: 'Undo' }));
    expect(screen.queryByRole('region', { name: 'Combo keys' })).toBeNull();
  });
});
```
