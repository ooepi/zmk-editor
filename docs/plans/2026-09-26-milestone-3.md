# Implementation plan — Milestone 3: layout canvas and layer/binding editing

Spec: [docs/specs/2026-09-26-zmk-editor-design.md](../specs/2026-09-26-zmk-editor-design.md)

## Core (`src/core`, test-first)

1. **Physical layout** — `layouts/lily58.ts` gets key positions copied from ZMK's `kata0510_lily58_layout` (x, y, w, h, rotation and its origin, in 1/100 key units).
2. **Keycode catalog** — `scripts/gen-keycodes.mjs` generates `catalog/keycodes.data.ts` from ZMK's `keys.h` for a given ref: canonical name, aliases, deprecated aliases, description, HID page, shifted.
   `catalog/keycodes.ts` adds:
   - categories;
   - short keycap labels (derived from the description, with curated overrides);
   - lookup by any alias;
   - ranked search;
   - modifier functions (`LC(…)`, `LG(…)`), parsed and formatted.
3. **Behavior catalog** — `catalog/behaviors.ts`. Each built-in behavior (`kp`, `mt`, `lt`, `mo`, `tog`, `to`, `sl`, `sk`, `kt`, `trans`, `none`, `bt`, `out`, `ext_power`, `mkp`, `mmv`, `msc`, `caps_word`, `key_repeat`, `gresc`, `bootloader`, `sys_reset`, `rgb_ug`, `bl`) has a name, a group and typed params: keycode, layer, enum with an optional number, number, or raw.
   Behaviors defined in the keymap join the catalog:
   - a hold-tap takes its param types from its own `bindings`;
   - other behaviors get raw params from `#binding-cells`.
4. **Binding display** — `keymap/display.ts`: `describeBinding` → `{ tap, hold?, kind }` for keycaps. Hold-taps show the hold label, and layer behaviors show layer names.
5. **Edit operations** — `keymap/edit.ts`, pure functions:
   - `setBinding`, `changeBehavior` (keeps compatible params and fills defaults for the rest);
   - `addLayer`, `renameLayer`, `moveLayer`, `deleteLayer`.
   Moving or deleting a layer renumbers every layer reference: layer bindings, sensor bindings, behavior and macro bindings, combos, conditional layers, and `#define`d layer numbers.
   On delete:
   - a `&lt` pointing at the deleted layer becomes `&kp <tap key>`;
   - other references to it become `&none`;
   - a combo that only worked on that layer is removed.

## UI (`src/ui`)

1. **State** — an editor reducer (config, selected layer and key, undo/redo). Work in progress is saved to localStorage. The first run loads the Lily58 demo config.
2. **Keyboard canvas** — keys are absolutely positioned from the physical layout and scale with the container (percentages plus container-query font sizes). Keycaps show the tap label large and the hold label small. Layer keys, `&trans` and `&none` each have their own style. A key can be selected with the mouse or the keyboard.
3. **Layer bar** — tabs; add, rename (double-click), move left/right, delete (with confirmation).
4. **Binding panel** — pick the behavior (grouped), then edit each param with its own control:
   - keycode picker: search, category filters, modifier toggles;
   - layer select, enum select or number input.
   A raw text field allows editing the binding source directly.
5. **Toolbar** — undo/redo, open a `.keymap` file, download the generated `.keymap`, reset to the demo, theme toggle.
6. **Shortcuts** — Ctrl+Z / Ctrl+Shift+Z undo and redo; Delete sets the selected key to `&trans`; Escape deselects.

## Tests

- Core unit tests: layout, catalog search and aliases, `describeBinding`, every edit operation (including renumbering), and the fixture round-trip after edits.
- UI tests (jsdom + Testing Library): the demo renders 58 keys; select a key → pick a keycode → the keycap updates and undo restores it; add, rename and delete a layer.
