# Implementation plan — Milestone 4: behaviors, combos, macros and encoders

Spec: [docs/specs/2026-09-26-zmk-editor-design.md](../specs/2026-09-26-zmk-editor-design.md)

Property names, defaults and enums come from ZMK v0.3's devicetree bindings (`app/dts/bindings`).

## Core (`src/core`, test-first)

1. **Property schemas** — `catalog/properties.ts`. Each property has a name, a label, a type (number, bool, enum, mods, key positions) and ZMK's default. There are schemas for hold-tap, mod-morph, macro, sensor-rotate and combos.
   Typed `readProperty`/`writeProperty` work on `DtProperty[]`. Writing `undefined` removes the property, so ZMK's default applies. Mods are read from and written as `<(MOD_LSFT|MOD_RSFT)>`.
2. **Behavior editing** — `keymap/behaviorEdit.ts`:
   - `createBehavior(kind)` makes a hold-tap, mod-morph, sensor-rotate or macro with sensible defaults and a unique label.
   - `replaceBehavior` swaps in an edited behavior.
   - `renameBehavior` also updates every `&label` reference.
   - `deleteBehavior` turns references into `&none` and reports how many there were.
   - `validLabel` rejects clashes with built-ins and other behaviors.
3. **Combo editing** — `keymap/comboEdit.ts`: `createCombo`, `replaceCombo`, `renameCombo`, `deleteCombo`, `toggleComboKey`.
4. **Encoders** — `keymap/sensorEdit.ts`: `sensorCount`, `setSensorBinding`. It fills other layers with `&trans` so every layer has one binding per encoder.
   The catalog gains sensor behaviors: `inc_dec_kp` (a keycode for each direction), plus the keymap's own sensor-rotate behaviors. `describeSensorBinding` gives the clockwise and counter-clockwise labels.
5. **Macros**:
   - The catalog gains the macro controls (`macro_tap`, `macro_press`, `macro_release`, `macro_pause_for_release`, `macro_wait_time`, `macro_tap_time`). They are shown only inside macros.
   - `keymap/macroText.ts` `textToBindings` turns text into `&kp` steps, using `LS(…)` for capitals and shifted symbols. It reports characters it can't type.

## UI (`src/ui`)

1. **View tabs** — Keymap, Combos, Behaviors, Macros.
2. **`BindingEditor`** — pulled out of the key panel so keys, combos, encoders, mod-morphs, sensor-rotates and macro steps can all use it. A context setting limits which behavior groups it offers.
3. **Keymap view** — an encoder strip under the keyboard, with one knob per encoder showing the clockwise and counter-clockwise labels for the current layer. Selecting a knob opens the encoder editor: either `inc_dec_kp` with two keys, or a sensor-rotate behavior.
4. **Combos view**:
   - The panel lists the combos; selecting one highlights its keys, and clicking a key adds or removes it.
   - The editor covers the binding, timeout, layers (none checked means all layers), name, and deleting the combo.
5. **Behaviors view** — lists the custom behaviors by kind, and can add a hold-tap, mod-morph or sensor-rotate.
   - A hold-tap editor picks the hold and tap behaviors and edits the properties.
   - Mod-morph and sensor-rotate editors edit their two bindings and properties.
   - Rename and delete are available for each behavior.
   - Other kinds, such as tap-dance, are shown read-only as source.
6. **Macros view**:
   - A list of macros, and a step list with move up/down and delete.
   - Selecting a step opens its binding editor.
   - Add a key tap, press/release/tap mode, or a wait; "Type text" adds several steps at once.
   - Wait and tap timing are editable.
7. **Edits and history** — every edit goes through one `edit` reducer action, so undo and redo cover all of them.

## Tests

- Unit tests for each core module.
- The Lily58 fixture still round-trips after each kind of edit.
- UI tests:
  - add a combo by clicking keys;
  - change an encoder to `inc_dec_kp` and pick keys;
  - create and rename a hold-tap and use it on a key;
  - build a macro with "Type text".
